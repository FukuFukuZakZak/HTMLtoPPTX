# HTML → PowerPoint beta：起動・配布手順

## 最初に使うとき

1. ZIPを展開してから `HTMLtoPPTX.exe` を起動します。設定とログを書き込めるフォルダーに置いてください。
2. 初回はスタンドアロンです。Microsoft Edge WebView2 Runtimeを使った専用画面が開きます。接続先は127.0.0.1、ポートは空き番号を自動選択します。
3. 歯車の「アプリ設定」から、次回の起動モード・IP・ポートを保存します。
4. メイン画面の×で終了し、EXEをもう一度起動します。起動設定はこの時点で反映されます。

スタンドアロンのメイン画面を閉じると、ヘルプ画面とローカルサーバーも終了します。ヘルプだけを閉じてもメイン画面は終了しません。最小化や再読み込みでは終了しません。同じ設定のEXEを再度起動すると、既存画面を表示します。OSの前面表示制限によりタスクバーから選択する必要がある場合があります。

変換は引き続き端末のWebView2／ブラウザ内で行います。「ZIPを保存」でダウンロードし、展開してPowerPointで開いてください。画面を閉じると作業中の入力は失われるため、保存完了後に閉じてください。

## 必要な実行環境

配布EXEはWindows x64用です。スタンドアロンにはMicrosoft Edge WebView2 Runtimeが必要です。未導入の場合は起動時に案内を表示します。アプリから自動インストールはしません。インターネットに接続できない端末には、管理者がMicrosoftの **Evergreen Standalone Installer（x64）** を持ち込んで導入してください。Webモードだけを実行するサーバーにはWebView2 Runtimeは不要です。

- [Microsoft WebView2 配布方式](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)
- [Microsoft WebView2 Runtime ダウンロード](https://developer.microsoft.com/microsoft-edge/webview2/)

## 庁内Webサーバーとして起動

Webモードは固定ポートです。既定8080、1～65535で変更可能です。使用中の番号ではエラーで停止し、別の番号には切り替えません。

IPの自動取得では有効なIPv4候補からプライベートアドレスを優先します。VPNや複数NICがある端末では、設定画面の候補を確認して庁内LANのIPを指定してください。IPが変わるとURLも変わります。共有URLを安定させるにはサーバー側の固定IPまたはDHCP予約を推奨します。未割当IP、127.0.0.1、0.0.0.0はWeb用の指定IPとして使えません。

1. サーバー上で一度EXEを普通に起動し、設定画面でWebモード・IP・固定ポートを保存して閉じます。
2. タスクスケジューラの「タスクの作成」で次のように設定します。

| 項目 | 設定例 |
|---|---|
| 実行アカウント | サーバー運用用アカウント。EXEと設定・ログ保存先に必要な権限を付与 |
| 全般 | ユーザーがログオンしているかどうかにかかわらず実行する |
| トリガー | スタートアップ時。ネットワーク準備のため30秒～1分遅延 |
| プログラム | `C:\Apps\HTMLtoPPTX\HTMLtoPPTX.exe` |
| 引数 | `--background --config "C:\Apps\HTMLtoPPTX\HTMLtoPPTX.config.json"` |
| 開始（オプション） | `C:\Apps\HTMLtoPPTX` |
| 条件 | 運用に応じてAC電源・ネットワーク条件を確認 |
| 設定 | 実行時間による強制停止を無効。失敗時は1分間隔で再起動、例：3回 |
| 既に実行中の場合 | 新しいインスタンスを開始しない |

EXEを直接指定してください。bat/cmdを挟む必要はありません。EXEはGUIサブシステムでビルドしてあり、Webモードは画面もブラウザも開きません。`--background` は初回未設定のスタンドアロンを誤って無人起動しないための指定も兼ねています。

3. タスクを実行し、設定ファイルと同じ場所の `.log` に記録された `URL=http://...` を確認します。
4. 庁内クライアントからそのURLを開きます。Windowsファイアウォールは管理者が対象の庁内ネットワーク・必要な送信元・固定TCPポートに限定して許可してください。アプリがルールを自動変更することはありません。
5. ブラウザを閉じてもサーバーは継続します。サーバー再起動後の自動起動も本番のタスク実行アカウントで確認してください。

このbetaのWeb接続はHTTPで、アプリ自体には利用者認証を設けていません。課内の管理されたネットワーク向けです。外部公開や認証が必要な配置は別途設計してください。変換元HTML／PPTXはサーバーへ送信しません。

## 設定変更と停止

設定ファイルの既定位置はEXEと同じフォルダーの `HTMLtoPPTX.config.json` です。管理用の起動でもタスクでも、同じ `--config` 絶対パスを指定してください。

サーバー端末上で設定を変更：

```text
HTMLtoPPTX.exe --configure --config "C:\Apps\HTMLtoPPTX\HTMLtoPPTX.config.json"
```

起動中のWebサーバーがある場合は、その端末の通常ブラウザにローカル管理画面を開きます。サーバー停止中は、一時的なスタンドアロンの専用画面を開きます。いずれも保存だけでは稼働中の設定を変更しません。通常のWeb利用者には起動設定は表示されません。

停止：

```text
HTMLtoPPTX.exe --stop --config "C:\Apps\HTMLtoPPTX\HTMLtoPPTX.config.json"
```

変更後は上記で停止してからタスクを実行します。設定ファイルを手編集する場合も停止してから行ってください。

## 保存されるもの・障害時

| 保存先 | 内容 |
|---|---|
| 設定ファイル | 次回の起動モード、IP、ポート |
| 設定ファイル名 + `.log` / `.log.1` | 起動URL、停止、エラー。各約1MiBでローテーション |
| 設定ファイル名 + `.lock` | 重複防止用。ファイルが残っていてもOSロックが解放されていれば再起動可能 |
| 設定ファイル名 + `.runtime.json` | PIDと現在の接続先、ローカル管理用の一時情報。正常終了で削除 |
| `%LOCALAPPDATA%\HTMLtoPPTX\WebView2\...` | アカウント・設定パスごとのWebView2プロファイル |

設定フォルダーは管理者と実行アカウントが扱う場所にし、一般利用者へ共有しないでください。とくに `.runtime.json` は診断動画や問い合わせ資料に添付しないでください。異常終了後は同じEXE・設定で再起動できます。別の設定パスは別インスタンスとして扱います。重複を避ける運用では同じパスに統一してください。

テーマはブラウザの接続先ごとに保存されるため、スタンドアロンの自動ポートが変わった場合は初期状態になることがあります。起動モード・IP・ポートは設定ファイルに保存されるため影響しません。

起動しない場合はログの「起動エラー」を確認します。固定ポートの競合、指定IP未割当、設定フォルダーの書込権限、WebView2 Runtime未導入の順に確認してください。起動失敗時は非ゼロの終了コードを返すため、タスクスケジューラから失敗を検出できます。

## 課内検証で確認すること

- 導入先端末でWebView2画面が開くこと、実データからZIPを保存してPowerPointで開けること。
- メイン画面を閉じた後にEXEが終了し、再起動できること。
- 対象サーバーの実行アカウントで、未ログオン／OS再起動後にもタスクが稼働すること。
- 別端末から固定URLへアクセスでき、ブラウザを閉じてもサーバーが継続すること。
- 実際のNIC選択、ファイアウォール範囲、設定フォルダー権限が庁内運用に合うこと。

導入先のアカウント権限・ネットワーク・OS再起動は開発端末の検証だけでは確定できないため、上記を課内で確認してください。
